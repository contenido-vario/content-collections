¿Qué se guarda en la carpeta public?

Almacena archivos estáticos puros que se deben servir tal cual están, sin ser procesados, optimizados ni compilados por Astro. Todo lo que se coloque aquí se copiará exactamente igual a la raíz del sitio final.

¿Qué tipo de cosas se colocan aquí?

  • Imágenes, íconos y otros recursos estáticos (por ejemplo, favicon.ico, favicon.svg, etc.).
  • robots.txt y sitemap.xml (para buscadores).
  • manifest.json (para Progressive Web Apps).
  • Fuentes web locales (.woff2, .ttf).
  • PDF descargables o imágenes que no se deseen optimizar automáticamente.
  • Archivos HTML que no necesitan ser procesados por Astro (por ejemplo, index.html).
  • Cualquier otro archivo que deba permanecer sin cambios y ser accesible directamente desde la raíz del sitio.
  • Integraciones y paneles administrativos estáticos (como Decap CMS):

Para DecapCMS (antes Netlify CMS), la carpeta public es clave. En ella se coloca:

  • public/admin/index.html: El HTML que carga la interfaz del panel de control de DecapCMS.
  • public/admin/config.yml: El archivo de configuración de las colecciones para DecapCMS.

¿Se sube al hosting o producción?

No se sube como carpeta fuente, pero cuando se ejecuta pnpm run build, Astro toma todo el contenido interno de public y lo coloca directamente en la raíz de la carpeta dist. Por lo tanto, termina publicado en el servidor.


Notas adicionales

Además de Decap CMS, en la carpeta public se suelen colocar archivos de muchas otras integraciones que requieren estar disponibles en URLs fijas o que necesitan ejecutar scripts estáticos sin la intervención de la compilación de Astro.

1. Archivos de Verificación y Propiedad de Dominio

Muchos servicios externos piden subir un archivo HTML o TXT específico a la raíz del dominio para demostrar que eres el dueño del sitio. Ejemplos:

  • Google Search Console: public/google123456789.html
  • Pinterest Domain Verification: public/pinterest-xxxx.html
  • Let's Encrypt / Certbot: Archivos temporales dentro de public/.well-known/acme-challenge/ para emitir certificados SSL.

2. Scripts de Analítica y Widgets de Terceros (Self-Hosted)

Si se prefieres servir de forma autónoma los scripts de seguimiento por privacidad o rendimiento en lugar de cargarlos desde un CDN externo:

  • Plausible Analytics / Umami: Se sube public/js/script.js para medir las visitas sin bloquear la velocidad del sitio.
  • Service Workers (PWAs): Archivos como public/sw.js que se encargan de gestionar la caché offline en navegadores y enviar notificaciones push.

3. Estándares de Seguridad y Privacidad

  • public/.well-known/security.txt: Un archivo estándar donde defines cómo los investigadores de seguridad pueden reportarte vulnerabilidades.
  • public/ads.txt o public/app-ads.txt: Archivos requeridos por plataformas como Google AdSense para autorizar quién puede vender anuncios en tu sitio.
